# Картковий каталог Pullora

Погоджено користувачем 2026-10-24 після `replica-recon`: картки, описи, посилання та основні дії. Режим поверхні: Operate. Джерело структури: два офіційні скриншоти ArtCraft із `../screens/README.md`. Візуальні значення походять із чинного Pullora: `src/styles/Cinematic.css` і `src/App.css`.

## Компонування

Каталог займає ширину робочої області. Папки залишаються секціями; їхні заголовки згортають і розгортають картки. Toolbar містить чинні фільтри, sort, пошук, refresh і compact.

Сітка: дві колонки на 1000px, три від 1180px, чотири від 1600px. На вузькому браузерному preview сітка має одну колонку. Desktop-перевірки виконуються на погоджених 1000×700, 1280×720 і 1920×1080.

## Картка

Порядок читання: вибір і зовнішні посилання; іконка/назва/owner; короткий опис; статус і версії; основна кнопка й меню. Опис займає до двох рядків, повний текст доступний у подробицях. Довгі назви переносяться до двох рядків, owner обрізається. Відсутній опис має локалізований текст.

Картка є `article role=group`, назва відкриває подробиці через звичайний button. Native checkbox керує масовим вибором; Ctrl/Shift-click та Ctrl+Space збережено. Посилання й кнопки не запускають click картки. Клавіатура має видимий focus; Escape закриває меню з поверненням у його trigger. Основна кнопка показує Install / Launch / Update.

Під час операції її зона містить етап, відсоток, обсяг і `role=progressbar`. Невідомий загальний розмір не дає вигаданого відсотка. Скасування доступне лише для queued/downloading; перевірка, розпакування, встановлення та перевірка запуску його не показують. Повторне скасування блокується на час запиту. При помилці дія лишається доступною з повідомленням, а при успіху клавіатурний focus повертається до основної кнопки. Первинна дія в меню також недоступна під час операції.

Прогрес змінює лише transform власної смуги через чинний motion-токен; ширина контейнера стала. Спільний reduced-motion контракт прибирає transform із transition. Labels і визначення етапів, дозволу скасування та числових меж спільні з наявним DownloadProgressPanel.

Статуси наявні: available, installed, update. Функції папок, обраного, обкладинки й фону залишилися в наявному portal-меню. Порядкові номери та порівняння з іншими продуктами не вводяться.

## Посилання

GitHub використовує наявний `html_url` і незмінену GitHub-only команду. Website береться з `homepage`; показуються тільки HTTPS-адреси без credentials і нестандартного порту. Rust повторює перевірку. Windows відкриває Website через `ShellExecuteW`, без shell-команди. Невдала дія показує чинне повідомлення про помилку.

## Подробиці

Відкриваються як inline-панель над картками. Повторно використані `LibraryHero`, `LibraryOperationsPanel` та чинні version/details-компоненти. Панель отримує focus, закривається кнопкою або Escape й повертає focus у виклик. Центр оновлень лишається в режимі Updates незалежно від панелі подробиць.

## Токени

Авторитетний runtime CSS: `src/features/library/LibraryCatalog.css`. У ньому містяться нові catalog-токени; кольори, шрифт, радіуси, action/focus і surface беруться з чинної системи. `tokens.json` документує зіставлення. Окремий `tokens.css`, Tailwind config чи нову бібліотеку не додаємо: застосунок уже має власну CSS-систему.

## Стан каталогу

Нижній рядок показує час отримання даних бібліотеки, поточне завантаження або повідомлення про невдале оновлення зі збереженими даними. Це не твердження про свіжість відповіді GitHub: backend може повертати кеш без окремої ознаки джерела. Фонових запитів чи таймера заради цього рядка немає.

## Перевірки

`scripts/ui/check-library-catalog.py` використовує production UI і mocked Tauri bridge. Він перевіряє теми, мови, три розміри, compact, довгий/порожній опис, безпечні посилання, keyboard/focus, меню, bulk selection, install/update, empty та error. Знімки в `../clone-screens/` містять тестові дані. Нативне відкриття браузера потребує Windows build/smoke-test; локальний MSVC linker відсутній.
