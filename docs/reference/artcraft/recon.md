# ArtCraft Launcher: структура інтерфейсу

Дата: 2026-10-24.
Платформа: desktop; офіційні скриншоти показують macOS.
Ціль: організація карток, описів, посилань і дій для Pullora.

Користувач погодив аналіз ArtCraft як референсу й уточнив, що цікавиться структурою UI. Ця карта зберігає спостереження recon і порівняння з базовим Pullora v5.22.1. Подальшу погоджену реалізацію описано в `build-log.md` і `design/components.md`.

## Основний сценарій

Користувач знаходить програму в каталозі, читає коротке пояснення, бачить її стан і версію та вибирає основну дію або зовнішнє посилання без попереднього відкриття подробиць.

## Екрани

| ID | Екран | Як знайти | Призначення | Основні елементи | Спостережені стани |
| --- | --- | --- | --- | --- | --- |
| S01 | Каталог Grid | Активний перемикач Grid у R02 | Вибір програми через самодостатні картки | Header, toolbar, групи, сітка у три колонки, footer | Доступна; встановлена; є оновлення; завантаження |
| S02 | Каталог Table | Активний перемикач Table у R03 | Швидке порівняння програм і версій | Ті самі фільтри; таблиця App / Inspired by / Status / Installed / Latest / Released; дії праворуч | Доступна; встановлена; є оновлення; завантаження; пауза; reconnecting |

На жодному з двох скриншотів немає відкритої панелі подробиць, меню чи Settings. Empty, error і loading всього каталогу не показані. Видима кнопка Settings підтверджує лише точку входу.

## Структура вікна

```text
Header: бренд | розділ лаунчера | Grid / Table | спільнота | refresh | settings
Toolbar: фільтри з кількістю | сортування (видиме в Grid) | пошук | Update all
Контент: група програм -> сітка карток або таблиця
Footer: час останньої перевірки | посилання лаунчера | платформа інсталяції
```

Фільтри R02/R03: All, Installed, Updates, Not installed. Це фільтри одного каталогу; жоден зі скриншотів не доводить наявність окремих сторінок для них. У Grid є заголовок групи Classic apps і лічильник групи. Відсутність зовнішніх проміжків між картками та спільні тонкі межі створюють вигляд єдиної таблиці з великими комірками.

Видимий рядок порівняння з комерційними програмами є особливістю каталогу Craft. Для загальних GitHub-програм у Pullora немає такого підтвердженого поля; його перенесення не пропонується.

## Опис і посилання

- Назва, короткий опис і стан читаються без відкриття іншого екрана.
- Website / GitHub у верхній смузі картки стосуються програми.
- Website / GitHub / Discord у footer стосуються лаунчера та його спільноти.
- Повний опис, README або release notes не показані в референсних зображеннях. Їхній екран і спосіб відкриття залишаються невідомими.
- На S02 довгі описи обрізані; назва, статус, версії й основна дія залишаються окремими стовпцями.

## Пропозиція картки Pullora

Це схема для обговорення, не готовий дизайн або працюючий екран.

```text
Картка програми
├─ Посилання: офіційний сайт (якщо є) | GitHub
├─ Іконка + назва
│  └─ owner/repo дрібнішим текстом
├─ Короткий опис: до двох рядків
├─ Текстовий статус
├─ Встановлена версія -> доступна версія | дата релізу
└─ Основна кнопка: Встановити / Запустити / Оновити | меню
```

Клік на назві або окрема дія "Докладніше" відкриває чинну панель: повний опис, метадані, release notes, список версій і файлові дії. Це пропозиція для Pullora; її немає на двох скриншотах ArtCraft.

Для першого етапу рекомендовано картковий каталог із цією ієрархією. Наявна навігація Library / Settings / About і папки залишаються доступними. Повний табличний режим, категорії Craft і порядкові номери карток не потрібні для прийняття цієї структури.

## Матриця і межі

Див. `features.csv`: 9 must, 3 should, 2 could, 3 skip. Після погодженої реалізації всі 9 must мають `yes`. Inline progress і рядок стану каталогу також реалізовані; Website має `partial` через відкрите native QA. `clone=no` означає, що відповідне розширення за цим дослідженням не реалізоване. Результати перевірок наведено в `build-log.md`, `test-plan.md` і `parity.md`.

З поточного завдання виключено аналіз інсталятора, заміну стека, нові фонові функції, перенесення бренду чи логотипів, каталог Craft та дослідження відгуків. Дані й назви програм на скриншотах є прикладами оригіналу, а не каталогом або відгуками Pullora.

## Обсяг і відкриті питання

Спостережено 2 подання каталогу, 4 сценарії входу та 5 інформаційних сутностей. Дослідження структури має розмір S. Реалізацію всього UI не оцінювали.

Найскладніші місця майбутньої роботи: умістити довгі назви й описи в рівні картки; забезпечити однакову доступність основної дії та посилань; показувати лише підтверджений Website. Responsive grid, focus, error і empty потребують власних перевірок Pullora.

Recon став основою погодженого компонування на наявній дизайн-системі. Поточна реалізація й обмеження зафіксовані в `build-log.md` та `parity.md`. Окремої перебудови архітектури ця карта не обґрунтовує.

## I01: встановлення, 2026-10-25

Користувач розширив обсяг: одна дія для останнього stable portable EXE/повного ZIP; setup/MSI лише за відсутності portable; вибір файла при неоднозначності. Окремо погоджено стандартну `C:\Program Files\Pullora\Apps`, звичайний запуск Pullora й UAC тільки для файлових операцій. Старі встановлення й вибрані папки не переносимо.

Публічний [README ArtCraft](https://github.com/storytold/craft-launcher#features), SHA `8ad962a57839b0c3b88993731784f12977e8b286`, описує автоматичний вибір OS/CPU-пакета й Windows MSI у Program Files. Він не доводить відсутності системних діалогів; runtime ArtCraft не запускали, код не читали. Pullora використовує свій downloader і власний вибір portable/ZIP. Штатна операція Windows описана в [IFileOperation flags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags).
