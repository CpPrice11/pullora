# Правила розробки Pullora

## Вибір технологій

- Rust — пріоритетна мова для логіки застосунку з орієнтацією на максимальну продуктивність; правила винятків наведено нижче.
- Tauri — пріоритетний фреймворк для десктопного застосунку та інтеграції інтерфейсу з Rust. У межах чинного стеку інтерфейс створювати через Tauri з наявним React/TypeScript шаром відображення, поєднуючи продуктивність і якісний вигляд.

## Rust — основна мова

- Нову бізнес-логіку, обробку даних, файлові й мережеві операції та фонові задачі реалізовувати на Rust.
- Наявну логіку іншими мовами переносити в Rust поступово, під час роботи над відповідними функціями. Не переписувати весь застосунок заради самого переходу.
- Іншу мову використовувати лише тоді, коли конкретну функцію технічно неможливо реалізувати на Rust у погодженому стеку й середовищі. Спочатку перевірити можливості Rust, наявних бібліотек та інтеграцій. Складність реалізації або зручність іншої мови самі собою не є підставою для винятку.
- Для винятку коротко зафіксувати технічне обмеження та причину вибору іншої мови. Обмежити її використання тією частиною функції, яка цього потребує; решту логіки залишити на Rust.
- Чинний React/TypeScript UI поки підтримувати як шар відображення та взаємодії з Rust через Tauri. Це погоджений перехідний стан: нові бізнес-правила не дублювати у frontend, локальні візуальні стани не переносити через IPC без потреби. Повну заміну UI-фреймворку погоджувати окремо.
- Після перевіреного перенесення прибирати замінену реалізацію, зберігаючи функції, налаштування, дані та локалізацію English/Українська.
- Сумісність перевіряти тестами відповідних сценаріїв, а приріст швидкодії підтверджувати вимірюваннями. Заміна мови сама собою не доводить прискорення.

## Структура файлів

- Зберігати стандартні корені `src` для UI та `src-tauri` для Rust/Tauri; налаштування інструментів залишати в потрібних їм місцях.
- Документацію класти в `docs`, дослідження ArtCraft — у `docs/reference/artcraft`.
- Скрипти групувати за призначенням: `scripts/checks`, `scripts/ui`, `scripts/release`. При перенесенні оновлювати команди npm, GitHub Actions і всі залежні шляхи.
- Згенеровані знімки, порівняння й звіти класти в `.artifacts`; кеші, локальну пам’ять та допоміжні інструменти не додавати до Git.
- Повна карта каталогів: [docs/PROJECT_STRUCTURE.md](docs/PROJECT_STRUCTURE.md).

## Авторство комітів

- Усі коміти цього проєкту оформлювати від імені користувача: `CpPrice11 <117557975+CpPrice11@users.noreply.github.com>` як author і committer, щоб GitHub пов’язував зміни з його акаунтом.
- Використовувати локальні Git `user.name` і `user.email` проєкту; не змінювати глобальні налаштування Git.
- Не додавати Claude, Codex, OpenAI, Anthropic чи інших ШІ-асистентів як авторів або в `Co-Authored-By`. Інше авторство можливе лише за окремим прямим дорученням користувача.
- Це правило визначає авторство; воно не є дозволом створювати коміт, виконувати push або переписувати історію без відповідного доручення.

- Локальну пам’ять і roadmap не додавати до Git без прямого доручення користувача.
